## 2. 사용자 입장에서 뭐가 달라졌나

### 2.1 카드 레이아웃 변경

- **이전:** 한 줄짜리 텍스트 카드 (제목, 책임자, 기간, 분야 뱃지)
- **이후:** 좌측 표지 영역(120px) + 우측 본문, 두 열 그리드. KEI E-library 리스트 뷰와 동일한 구조.

### 2.2 표지 자리 (Placeholder)

- 현재 데이터에는 표지 이미지 URL이 없으므로, 모든 카드는 **KEI 그린 그라디언트 + 제목 첫 두 글자** 자리표시자로 표시됩니다.
- 예: 제목 "Supporting Danyang's Bid…" → `SU` 라벨이 표지 자리에 표시.
- 표지 영역 크기: 가로 120px × 세로 168px (5:7 비율, 책 표지 비율).

### 2.3 표지를 진짜로 띄우려면

- `data/projects.xlsx`의 `Cover URL` 컬럼에 KEI E-library의 표지 이미지 URL을 적으면 그 카드만 실제 이미지로 바뀝니다.
- 코드 변경 불필요. 데이터만 수정하면 즉시 반영됩니다.
- URL은 `https://...` 또는 로컬 `data/...` 만 허용 (보안).

### 2.4 모바일 대응

- 화면 폭 640px 이하 → 표지 80px로 축소, 간격 12px로 좁힘.

### 2.5 안 바뀐 것 (회귀 0건)

- 검색, 분야 필터, 기간 필터, Type/Year facet, 정렬, PDF/Excel 내보내기, 상세 모달, 다국어 토글, 키보드 단축키 — 전부 그대로.

## 3. 개발자 입장에서 뭐가 달라졌나

### 3.1 데이터 계약 (`scripts/data/contract.js`)

9개의 새 optional 컬럼이 contract에 추가됐습니다. 모두 빈 값 허용, 기존 회귀 0건.

| 컬럼명 (스프레드시트) | 키 (코드)       | 용도                                                         |
| --------------------- | --------------- | ------------------------------------------------------------ |
| DOI                   | `doi`           | 학술지 DOI (10.xxxx/yyyy 형식)                               |
| ISBN                  | `isbn`          | 단행본 식별자                                                |
| ISSN                  | `issn`          | 학술지 식별자                                                |
| Authors               | `authors`       | 저자 목록 (책임자 외)                                        |
| Published             | `publishedDate` | 발간일                                                       |
| Abstract              | `abstract`      | 초록                                                         |
| Source                | `source`        | 출처 (`research` / `elibrary` / `journal` / `working-paper`) |
| Cover URL             | `coverUrl`      | 표지 이미지 URL                                              |
| E-library URL         | `elibUrl`       | KEI E-library 원문 페이지 URL                                |

각 컬럼은 한국어 별칭도 인식합니다 (예: "발간일" → `publishedDate`, "요약" → `abstract`, "출처" → `source`).

### 3.2 데이터 검증 (`scripts/validate-data.mjs`)

경고만 출력 (실패 아님 — 종료 코드 0 유지):

- `DOI` 형식 어긋남: `^10\.\d{4,9}/[-._;()/:A-Za-z0-9]+$` 정규식
- `Cover URL` / `E-library URL`: `https://` 또는 `data/`로 시작 안 함
- `Source`: 화이트리스트 외 값
- 빈 값은 경고 대상 아님 (전부 optional)

### 3.3 헤더 자동 추가 (`scripts/fix-projects-xlsx.mjs`)

스프레드시트 정리 스크립트가 9개 신규 헤더를 자동으로 추가합니다.
**Idempotent** — 두 번째 실행 시 `columns added: 0` 출력 (중복 추가 없음).

### 3.4 카드 렌더 (`scripts/app.js`)

새 헬퍼 3개:

- `resolveCoverImage(project)` — 표지 URL 우선순위 결정 (`coverUrl` → `thumbnail` → null)
- `getProjectInitials(project)` — 제목의 첫 2 영숫자 (없으면 `KEI`)
- `createPlaceholderCover(project)` — `<div class="cover-placeholder">` 생성

`createProjectCard`의 출력 DOM:

```
.project-card                                ← 그리드 컨테이너
├── .project-card-cover                      ← 신규: 좌측 표지 영역
│   ├── <img class="cover-img"> | <div class="cover-placeholder">
│   └── <span class="cover-source-badge">    ← Source 있을 때만
└── .project-card-body                       ← 신규: 우측 본문 래퍼
    ├── <input class="project-checkbox">
    ├── <button class="project-title">
    ├── <div class="project-meta">
    └── <div class="project-badges">
```

이미지에는 `loading="lazy"`, `decoding="async"`, `onerror` 폴백(placeholder로 자동 교체) 적용.

### 3.5 CSS (`styles/main.css`)

신규 클래스 5개 + 모바일 분기:

- `.cover-placeholder` — KEI 그린 그라디언트 + 흰 굵은 텍스트 가운데 정렬

## 6. 의사결정 기록

### 6.1 Placeholder를 SVG가 아닌 `<div>+텍스트`로 결정

원래 계획은 `generatePlaceholderCover()` 함수가 SVG data URI를 반환하는 것이었지만, 실제 구현 중 다음 이유로 변경:

- CSS 그라디언트 + 텍스트 렌더만으로 동일한 비주얼 달성
- 카드마다 SVG data URI를 인코딩하는 비용 제거
- 접근성(aria-label) 일관성 확보 더 쉬움
- 스타일 변경 시 CSS 한 곳만 수정

→ `generatePlaceholderCover` 제거, PRD US-005 acceptance criteria 동기화.

### 6.2 firefox 병렬 flake 대응으로 retries: 1

같은 코드에 ci:local 여러 회차 실행했을 때 매 회차마다 다른 firefox 테스트가 무작위로 fail/pass — 격리 실행 시 100% 통과. 환경적 flake로 판단, 단일 retry로 안정화.

### 6.3 placeholder 생성 중복 제거 (deslop)

`createProjectCard`의 if/else 분기에서 placeholder 생성 코드 5줄이 두 번 반복됨 → `createPlaceholderCover(project)` 헬퍼로 추출. 향후 placeholder 스펙 변경 시 한 곳만 수정.

## 10. API 자동화 — 알아봐야 할 것들

DOI / 표지 / 저자 / 초록 등을 손으로 xlsx에 채우는 대신, 외부 API에서 자동으로 가져올 수 있다면 운영 비용이 크게 줄어듭니다. 어느 API에 어떻게 접근하는지 사용자(KEI 직원)가 사내·외에서 확인해야 할 항목들을 우선순위 순으로 정리합니다.

### 10.1 우선순위 1 — 사내에서 먼저 확인할 것

가장 먼저 답을 얻어야 자동화 설계가 가능한 항목들입니다.

#### A. KEI E-library가 자체 API를 제공하는가?

- **누구에게 묻는지:** KEI 정보전산팀 / E-library 운영 담당자
- **확인 포인트:**
  - 발간물 목록을 JSON/XML 등 기계 판독 가능한 형식으로 받을 수 있는지
  - 표지 이미지 URL 패턴이 표준화되어 있는지 (예: `https://www.kei.re.kr/elib/cover/{c_id}.jpg` 같은 규칙)
  - 인증(API 키)이 필요한지, rate limit 있는지
- **만약 있다면:** Phase 4(통합 검색)의 데이터 소스로 직결 — 야간 배치로 신간 발간물 자동 동기화 가능

#### B. KEI가 DOI를 발급하고 있는가? 어디로?

- **누구에게 묻는지:** KEI 연구지원팀 / 출판 담당
- **확인 포인트:**
  - KEI 보고서/학술지에 DOI를 발급한 이력이 있는지
  - 발급기관이 **CrossRef** 인지 **DataCite** 인지 (둘은 가입·운영 방식이 다름)
  - DOI prefix (예: `10.xxxx/...` 의 `xxxx` 부분)가 무엇인지
- **만약 있다면:** 그 prefix로 CrossRef/DataCite API에 일괄 조회 → 메타데이터/인용 정보 자동 채움

#### C. 기관 내부에 발간물 DB가 따로 있는가?

- **누구에게 묻는지:** 정보전산팀 / 연구지원팀
- **확인 포인트:**
  - RIMS(연구사업관리시스템) 같은 내부 시스템에 발간물 메타데이터가 별도로 관리되는지
  - 그쪽 DB를 export 받을 수 있는지 (CSV/JSON)
- **만약 있다면:** 외부 API보다 정확하고 가용성 높음 — 1차 데이터 소스로 활용

---

### 10.2 우선순위 2 — 무료 외부 API (가입만 하면 즉시)

가입 절차가 가볍고, 정책 연구·환경 분야에서도 충분히 커버되는 무료 API 들입니다.

#### D. CrossRef REST API

- **URL:** https://api.crossref.org
- **용도:** DOI 메타데이터 조회 (제목, 저자, 발간일, 초록, 저널/출판사, 인용 등)
- **가입:** 조회만이면 가입 불필요. 단, "polite pool" 사용을 위해 이메일을 헤더에 포함하면 우선 처리됨
- **비용:** 무료
- **한계:** 학술 출판물에 강함, 정책 보고서·회색 문헌은 누락 많음

#### E. DataCite REST API

- **URL:** https://api.datacite.org
- **용도:** 연구 데이터셋·보고서·회색 문헌의 DOI 메타데이터
- **가입:** 조회 무료, DOI 발급은 기관 회원 가입 필요
- **비용:** 조회 무료
- **메모:** KEI처럼 정책 연구 보고서를 내는 기관에는 CrossRef보다 더 적합할 수 있음

#### F. OpenAlex

- **URL:** https://api.openalex.org
- **용도:** CrossRef + Microsoft Academic + ORCID + ROR을 통합한 학술 그래프. 무료, API 키 불필요
- **비용:** 완전 무료
- **메모:** 한 번 호출로 저자·기관·인용·주제 키워드까지 한 번에 — 가장 가성비 좋은 옵션

#### G. ORCID Public API

- **URL:** https://pub.orcid.org/v3.0
- **용도:** 저자 식별자, 소속 이력
- **가입:** Public API는 무료, OAuth 등록 필요
- **메모:** 외국인 방문자에게 KEI 연구원 프로필을 정식으로 보여주려면 ORCID 연결이 신뢰도 높음

---

### 10.3 우선순위 3 — 국내 학술 API

국문 메타데이터/논문 정보가 필요할 때.

#### H. KCI(한국학술지인용색인) Open API

- **URL:** https://www.kci.go.kr (포털 → Open API 신청)
- **용도:** 국내 학술논문 메타데이터, 인용 정보
- **가입:** 신청 → 승인 → API 키 발급 (보통 며칠 소요)
- **비용:** 무료
- **메모:** KEI 연구원이 학술지에 게재한 논문을 자동으로 끌어올 때 핵심

#### I. RISS Open API (한국교육학술정보원)

- **URL:** http://www.riss.kr
- **용도:** 학위논문, 단행본, 학술지 통합 검색
- **가입:** 신청 필요
- **메모:** 정책 보고서보다는 학위/단행본 강점

#### J. NDSL (국가과학기술정보센터) — KISTI

### 10.4 우선순위 4 — 표지 이미지 자동화

#### K. Open Graph 이미지 추출

- **방법:** 각 발간물의 원문 페이지 URL(`elibUrl`)을 fetch → HTML의 `<meta property="og:image">` 추출
- **가입:** 불필요 (단, hotlink 차단 / 저작권 확인 필요)
- **메모:** KEI E-library 페이지가 og:image 메타를 제공한다면 가장 간단한 자동화 경로

#### L. CrossRef / OpenAlex의 cover image 필드

- 일부 출판물은 메타데이터에 cover URL을 포함. 표지 자동 매칭에 활용

### 10.6 사내에서 함께 정리해야 할 정책 사항

기술적으로 가능해도 정책상 막히는 경우가 있어, 미리 결재선 확인이 필요합니다.

| 항목                                            | 누구에게 / 무엇을                                            |
| ----------------------------------------------- | ------------------------------------------------------------ |
| 외부 API 호출 시 사내 네트워크 정책             | 정보전산팀 — 방화벽/프록시에서 막히는지                      |
| API 키 보관                                     | 보안 정책 — `.env` / 사내 secret manager / Vault 사용 가능성 |
| KEI E-library 자동 스크레이핑 가능 여부         | 운영 담당 + 법무 — robots.txt, 저작권, ToS                   |
| 외부 사이트 표지 이미지 hotlink 가능 여부       | 법무 — 라이선스 / 출처 표기 의무                             |

| 자동 업데이트 배치의 실행 환경                  | 정보전산팀 — 사내 cron 서버 / GitHub Actions 사용 가능 여부  |

### 10.7 실제 자동화 시 작업 흐름 (참고)
